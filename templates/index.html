Permissions

Deny-by-default access control: members vs. admins, plus fine-grained per-record permissions. Nobody sees data they weren’t granted.

{% include "components/icon.html" with name="network" class="h-5 w-5" %}

Network allowlist

Who can reach the app is controlled by the plain-text allowed_ips.txt file. It allows everyone by default; list office / VPN IP ranges there to lock it down to your network.

{% include "components/icon.html" with name="lock-keyhole" class="h-5 w-5" %}

Security hardening

Sign-in rate limiting (brute-force protection), a Content-Security-Policy, CSRF protection, and secrets kept out of the code (in your local .env).

{% include "components/icon.html" with name="zap" class="h-5 w-5" %}

Speed by default

Long lists paginate automatically, slow database patterns fail the tests before they ship, and slow work (e.g. email) runs in the background.

Data & UI

Starts on a zero-setup SQLite database (switch to SQL Server when you go live). Clean, fast Tailwind + HTMX interface — no Node or npm to install.

{# How to actually start building. #}

Next steps — start building

You build this app by describing what you want to Claude Code in everyday language. Claude asks questions, writes the tests, builds the feature, runs the checks, and shows you the result before saving.

  1. 1 Describe your first feature. For example: “Add an Invoice with a customer, an amount, and a due date. Only admins can delete them.”
  2. 2 Ask for the screens you want. “Show me a searchable list of customers, fast even with 50,000 of them.” Claude builds the list, search, and pagination.
  3. 3 Lock down access when you’re ready. Tell Claude to restrict the app to your office network (it edits allowed_ips.txt), and to set up Microsoft sign-in for your team.
  4. 4 Iterate. If something feels off, just say so — Claude can undo it and try again. Check the profile page to see your account details any time.

Tip: the house rules Claude follows live in CLAUDE.md, and step-by-step playbooks live in .claude/skills/.
